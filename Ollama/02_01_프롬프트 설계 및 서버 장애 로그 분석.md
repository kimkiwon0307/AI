# 2장 1교시 — 프롬프트 설계 및 서버 장애 로그 분석

## 1. 핵심 개념

| 개념 | 설명 |
|---|---|
| Prompt | AI에게 질문하거나 작업을 지시하는 입력 내용 |
| System Prompt | AI의 역할과 기본 동작 원칙을 지정 |
| User Prompt | 사용자 또는 프로그램이 현재 수행할 작업을 전달 |
| Token | AI가 텍스트를 처리하는 기본 단위 |
| Temperature | AI가 답변을 생성할 때 무작위성을 조절하는 설정 |
| Context Window | AI가 한 번에 참고할 수 있는 문맥의 범위 |

## 2. 좋은 프롬프트 작성 방법

프롬프트에는 다음 정보가 포함되면 좋다.

1. **역할(Role):** AI가 어떤 역할을 수행할 것인가?
2. **환경(Context):** 어떤 서버와 시스템에서 문제가 발생했는가?
3. **작업(Task):** AI가 무엇을 분석해야 하는가?
4. **출력 형식(Format):** 결과를 어떤 형식으로 제공할 것인가?
5. **제한 조건(Constraints):** 어떤 점을 주의해야 하는가?

### 예시

**잘못된 프롬프트**
```text
서버가 안 됩니다. 해결해 주세요.
```

**개선된 프롬프트**
```text
당신은 Linux 인프라 운영 보조 AI입니다.

환경:
- Ubuntu 24.04
- WEB: Nginx
- WAS: Tomcat (8080)

오류:
connect() failed (111: Connection refused)

요청:
1. 장애 증상을 설명하세요.
2. 가능한 원인 3가지를 알려주세요.
3. Linux 점검 명령어를 제시하세요.
4. 확인된 사실과 추측을 구분하세요.
```

## 3. System Prompt와 User Prompt 차이

**System Prompt**
```text
당신은 Linux 인프라 운영 보조 AI입니다.
장애 원인 후보와 점검 방법을 제시하세요.
확인되지 않은 원인을 단정하지 마세요.
```

**User Prompt**
```text
Nginx에서 502 Bad Gateway 오류가 발생했습니다.
다음 오류 로그를 분석해 주세요.
```

- System Prompt = AI의 역할과 기본 원칙
- User Prompt = 현재 해결해야 할 작업

## 4. Token · Temperature · Context

| 항목 | 핵심 |
|---|---|
| Token | AI가 텍스트를 처리하는 단위 |
| Temperature | 낮을수록 일반적으로 답변의 무작위성이 감소 |
| Context Window | 한 번의 추론에서 참고할 수 있는 문맥 범위 |

장애 분석에는 비교적 낮은 Temperature를 사용하는 것이 유용할 수 있다.

단, **Temperature가 낮다고 AI 분석이 반드시 정확해지는 것은 아니다.**

## 5. Ollama 실습 명령어

### Qwen 실행

```bash
ollama run qwen3:1.7b
```

### Qwen 대화창에서 설정

```text
/set parameter temperature 0.2
/set parameter num_ctx 4096
```

- `temperature 0.2`: 답변 생성의 무작위성을 낮춤
- `num_ctx 4096`: 문맥 크기를 4,096토큰으로 설정

### System Prompt 설정

```text
/set system 당신은 Linux 인프라 운영 보조 AI입니다. 장애 로그를 분석하고 원인 후보와 점검 명령어를 제시하세요.
```

## 6. 서버 장애 로그 분석

### Nginx 502 오류

```text
connect() failed (111: Connection refused)
while connecting to upstream
```

가능한 원인:
- WAS 서비스 중단
- WAS 8080 포트 미리스닝
- 잘못된 업스트림 주소 또는 연결 거부 설정

점검 명령어:

```bash
sudo nginx -t
sudo ss -lntp | grep 8080
sudo systemctl status marble
```

### Java Heap 메모리 오류

```text
java.lang.OutOfMemoryError: Java heap space
```

가능한 원인:
- Java 힙 크기 부족
- 과도한 메모리 사용
- 메모리 누수

점검 명령어:

```bash
free -h
ps -ef | grep '[j]ava'
sudo journalctl -u marble -n 50
```

### MySQL 인증 오류

```text
Access denied for user 'app'@'10.0.21.10'
```

가능한 원인:
- 잘못된 비밀번호
- 사용자 계정의 접속 호스트 불일치
- 인증 관련 설정 문제

점검 명령어:

```bash
sudo systemctl status mysql
sudo ss -lntp | grep 3306
```

## 7. AIOps에서의 프롬프트 활용

```text
서버 장애 발생
      ↓
Python이 장애 로그 수집
      ↓
System Prompt + User Prompt 구성
      ↓
Ollama API 호출
      ↓
Qwen이 로그 분석
      ↓
원인 후보 및 점검 방법 생성
      ↓
운영자가 실제 서버 상태 검증
```

현재는 사람이 직접 프롬프트를 입력하지만, 다음 교시에서는 Python으로 자동 전달한다.

## 8. 핵심 주의사항

- AI는 실제 서버를 자동으로 확인하는 것이 아니다.
- AI가 분석한 원인은 확정된 사실이 아니라 후보일 수 있다.
- 실제 장애 원인은 로그, 서비스 상태, 포트, 네트워크 등을 통해 검증해야 한다.
- AI가 제시한 명령어를 검증 없이 실행해서는 안 된다.
- 운영 로그에 포함된 비밀번호·API 키·개인정보 등 민감한 정보는 AI에 전달하기 전에 제거한다.

## 9. 최종 암기

**① Prompt = AI에게 작업을 지시하는 내용**

**② System Prompt = 역할·규칙 / User Prompt = 현재 작업**

**③ 좋은 프롬프트 = 역할 + 환경 + 작업 + 출력 형식 + 제한 조건**

**④ AI 장애 분석 = 원인 후보 제시 / Linux 명령어 = 실제 상태 검증**

**⑤ AIOps 목표 = Python이 로그를 수집하고 Qwen에 전달하여 장애 분석을 자동화하는 것**

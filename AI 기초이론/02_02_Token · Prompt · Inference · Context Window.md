
# AI 기초 이론 — 2장 2교시
## Token · Prompt · Inference · Context Window

### 1. 전체 동작 구조

사용자가 LLM에 질문하면 다음 과정을 거쳐 답변이 생성된다.

```text
사용자 질문 및 지시사항 (Prompt)
           ↓
텍스트를 토큰으로 변환 (Token)
           ↓
학습된 LLM이 추론 수행 (Inference)
           ↓
다음 토큰 예측 및 반복 생성
           ↓
최종 답변 출력
```

이때 모델이 한 번에 처리할 수 있는 문맥의 크기는 **Context Window**에 의해 제한된다.

---

### 2. Token(토큰)이란?

**Token은 LLM이 텍스트를 처리하는 기본 단위이다.**

우리는 글자와 단어로 문장을 읽지만, LLM은 문장을 토큰으로 나누고 숫자로 변환하여 계산한다.

예시:

`MySQL 연결 오류`

개념적으로 다음처럼 나뉠 수 있다.

`My` / `SQL` / `연결` / `오류`

실제 분리 방식은 모델의 토크나이저(Tokenizer)에 따라 달라진다.

#### 토큰이 중요한 이유

- 입력할 수 있는 텍스트 양과 관련된다.
- 생성할 답변의 길이와 관련된다.
- 토큰이 많아지면 처리 시간이 증가할 수 있다.
- 모델 실행 시 메모리 사용량에 영향을 준다.
- 유료 AI API는 토큰 사용량에 따라 비용이 발생할 수 있다.

**Marble 적용:** WAS에서 수집한 수많은 로그를 모두 보내기보다 장애 발생 시각과 관련된 오류 로그를 선별해 전달한다.

---

### 3. Prompt(프롬프트)란?

**Prompt는 AI에게 전달하는 질문, 지시사항, 상황 정보 등의 입력이다.**

같은 AI 모델이라도 어떤 정보를 전달하느냐에 따라 답변의 품질이 달라질 수 있다.

#### 정보가 부족한 프롬프트

"DB 오류가 발생했어. 해결해 줘."

어떤 DB인지, 어떤 오류인지, 현재 상태가 어떤지 알 수 없다.

#### 구체적인 프롬프트

"Ubuntu 24.04에서 Spring Boot와 MySQL 8을 사용하고 있습니다. WAS01에서 Communications link failure가 발생했으며, MySQL은 실행 중이지만 TCP 3306 연결은 실패합니다. 가능한 원인과 확인 방법을 설명해주세요."

이처럼 환경, 오류, 현재 상태, 원하는 결과를 구체적으로 전달하는 것이 좋다.

#### Prompt Engineering

AI가 원하는 작업을 수행하도록 프롬프트를 설계하는 방법이다.

```text
[역할]
Linux 및 AWS 장애 분석 도우미

[환경]
Ubuntu 24.04 / Spring Boot / MySQL 8

[장애 증거]
WAS01: DB 연결 실패
MySQL: 실행 중
TCP 3306: 연결 실패

[요청]
1. 가능한 원인 3가지
2. 원인별 확인 방법
3. 조치 시 주의사항

[제약]
확인되지 않은 원인을 확정하지 마세요.
```

**Marble 적용:** Python 프로그램이 수집한 장애 증거를 정리해 Qwen에 프롬프트로 전달한다.

---

### 4. Inference(추론)란?

**Inference는 이미 학습된 AI 모델에 새로운 입력을 전달하여 결과를 생성하는 과정이다.**

| 구분 | Training(학습) | Inference(추론) |
|---|---|---|
| 목적 | 모델이 패턴을 학습 | 학습된 모델을 사용 |
| 결과 | 모델의 가중치 조정 | 분석·예측·답변 생성 |
| 예시 | Qwen 모델 개발 과정 | Qwen으로 Marble 로그 분석 |

#### Ollama와 Qwen을 이용한 추론

```text
Python 프로그램
       ↓
장애 로그 + Prompt
       ↓
Ollama API
       ↓
Qwen 모델
       ↓
Inference 수행
       ↓
장애 분석 결과 생성
       ↓
Python이 결과 수신
```

Qwen은 이미 학습된 모델이므로 우리가 직접 모델을 학습시킬 필요는 없다.

**Marble 적용:** Python이 Ollama API에 장애 정보를 전달하면 Qwen이 원인 가설과 대응 방법을 생성한다.

---

### 5. Context Window(컨텍스트 윈도우)란?

**Context Window는 LLM이 한 번의 요청에서 처리할 수 있는 문맥의 최대 크기이다.**

문맥에는 다음 내용이 포함될 수 있다.

- 이전 대화 내용
- 현재 질문
- AI에 전달한 지시사항
- 참고 문서 및 장애 로그
- 생성 중인 답변

Context Window는 일반적으로 토큰 단위로 표현된다.

#### 예시

어떤 모델의 Context Window가 8,000토큰이라고 가정하자.

질문, 지시사항, 장애 로그에 많은 토큰을 사용하면 답변을 생성할 수 있는 공간이 제한될 수 있다.

실제 입력·출력 한도는 모델과 실행 환경에 따라 달라진다.

#### 문맥 한도를 초과하면?

- 요청이 실패할 수 있다.
- 입력 내용 일부가 잘릴 수 있다.
- 오래된 대화가 제외될 수 있다.
- 중요한 정보가 누락되어 분석 품질이 떨어질 수 있다.

#### Marble 적용

WAS01에서 수십만 줄의 로그가 생성되었다고 가정하자.

모든 로그를 AI에 전달하는 대신 다음과 같이 처리한다.

```text
Zabbix 장애 감지
       ↓
Python이 장애 발생 시각 확인
       ↓
ELK에서 관련 시간대 로그 검색
       ↓
ERROR 및 관련 로그 선별
       ↓
Qwen에 필요한 증거만 전달
       ↓
AI 장애 분석
```

**핵심:** AI에 무조건 많은 정보를 전달하는 것보다 필요한 정보를 정확히 전달하는 것이 중요하다.

---

### 6. 네 가지 개념 비교

| 개념 | 의미 | Marble 활용 |
|---|---|---|
| Token | LLM의 텍스트 처리 기본 단위 | 로그 입력 크기 관리 |
| Prompt | AI에 전달하는 질문·지시·정보 | 장애 분석 요청 작성 |
| Inference | 학습된 모델이 결과를 생성하는 과정 | Qwen 장애 분석 |
| Context Window | 한 번에 처리 가능한 문맥의 최대 크기 | 로그·문서 입력량 관리 |

### 7. Marble AIOps 전체 적용 구조

```text
Marble WEB/WAS/DB 장애 발생
             ↓
Zabbix 장애 감지
             ↓
Python 장애 정보 수집
             ↓
ELK 관련 로그 조회
             ↓
Python이 Prompt 구성
             ↓
Ollama + Qwen
             ↓
Token 변환 및 Inference
             ↓
AI 원인 가설·대응 방법 생성
             ↓
Python 복구 정책 및 안전 조건 확인
             ↓
허용된 단순 장애 자동 복구
             ↓
Health Check 및 Discord 알림
```

**주의:** AI가 생성한 복구 명령을 그대로 실행하면 안 된다. 실제 서버 상태와 사전에 정의한 안전 조건을 검증한 후 허용된 작업만 실행해야 한다.

---

### 8. 이번 교시 핵심 5가지

1. **Token:** LLM은 텍스트를 토큰 단위로 처리한다.
2. **Prompt:** AI에 질문과 상황 정보를 구체적으로 전달해야 유용한 분석을 얻을 수 있다.
3. **Inference:** 우리가 Qwen을 활용하는 것은 모델을 새로 학습시키는 것이 아니라 추론 기능을 사용하는 것이다.
4. **Context Window:** LLM이 한 번에 처리할 수 있는 문맥의 크기에는 한계가 있다.
5. **Marble AIOps:** 관련 로그를 선별하고 좋은 프롬프트를 작성해 AI에 전달하며, 분석 결과는 반드시 검증한다.

### 9. 복습 확인문제 및 정답

**Q1. LLM이 텍스트를 처리하는 기본 단위는?**

정답: Token(토큰)

**Q2. AI에 전달하는 질문, 지시사항, 상황 정보를 무엇이라고 하는가?**

정답: Prompt(프롬프트)

**Q3. 이미 학습된 Qwen으로 장애 로그를 분석하는 과정은?**

정답: Inference(추론)

**Q4. LLM이 한 번에 처리할 수 있는 문맥의 최대 크기를 무엇이라고 하는가?**

정답: Context Window(컨텍스트 윈도우)

**Q5. Marble 장애 로그가 너무 많을 때 적절한 방법은?**

정답: 장애 발생 시각 주변의 관련 로그를 선별해 AI에 전달한다.

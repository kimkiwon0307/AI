
# AI 기초 이론 — 1장 3교시
## 생성형 AI(Generative AI)

### 1. 생성형 AI란?

생성형 AI는 학습한 데이터의 패턴을 바탕으로 새로운 콘텐츠를 생성하는 인공지능 기술이다.

대표적인 생성 결과:
- 텍스트: 질문 답변, 문서 요약
- 코드: Python, Shell Script 작성
- 이미지: 그림 및 일러스트 생성
- 음성: 음성 및 음악 생성

**핵심:** 생성형 AI는 기존 데이터를 단순히 분류하는 것을 넘어 새로운 결과물을 생성한다.

### 2. 기존 AI와 생성형 AI의 차이

| 구분 | 분류 AI | 생성형 AI |
|---|---|---|
| 주요 목적 | 데이터 분류 및 예측 | 새로운 콘텐츠 생성 |
| 입력 예시 | 서버 오류 로그 | 서버 오류 로그와 분석 요청 |
| 출력 예시 | DB 연결 장애 | 장애 원인 및 대응 방법 보고서 |
| Marble 활용 | 장애 유형 분류 | 장애 분석 보고서 생성 |

생성형 AI도 분류 작업을 수행할 수 있으므로 두 기술이 완전히 분리된 것은 아니다.

### 3. 생성형 AI는 어떻게 동작할까?

GPT, Qwen 같은 LLM은 입력된 문맥을 참고하여 다음 토큰(Token)을 예측하는 과정을 반복하면서 문장을 생성한다.

동작 과정:

1. 사용자가 질문이나 데이터를 입력한다.
2. 입력 내용을 토큰 단위로 처리한다.
3. 학습한 패턴과 문맥을 바탕으로 다음 토큰을 예측한다.
4. 토큰 생성을 반복하여 답변을 완성한다.

**Token:** AI가 텍스트를 처리하는 기본 단위로, 글자·단어·단어 일부 등이 될 수 있다.

### 4. 주요 AI 용어

| 용어 | 의미 |
|---|---|
| AI | 인공지능 전체 분야 |
| 생성형 AI | 텍스트·코드·이미지 등을 생성하는 AI |
| LLM | 대규모 언어 모델 |
| GPT / Qwen | LLM 모델 계열 |
| Ollama | AI 모델을 실행하는 프로그램 |
| Prompt | AI에 전달하는 질문이나 지시문 |
| Inference | 학습된 AI 모델을 사용하는 과정 |

### 5. 프롬프트 엔지니어링(Prompt Engineering)

AI에 질문과 관련 정보를 구체적으로 전달하여 더 유용한 결과를 얻도록 하는 방법이다.

예시:

나쁜 예:
"DB 오류가 발생했어. 해결해 줘."

좋은 예:
"Ubuntu 24.04에서 Spring Boot와 MySQL을 사용합니다. WAS에서 Communications link failure가 발생했습니다. 가능한 원인과 확인 방법을 설명해 주세요."

**핵심:** AI에 충분한 상황 정보와 구체적인 요청을 전달하는 것이 중요하다.

### 6. 생성형 AI의 한계

- 환각(Hallucination): 사실과 다르거나 근거 없는 답변 생성
- 문맥 부족: 제공되지 않은 서버 상태는 알 수 없음
- 최신 정보 부족: 모델이 최신 설정이나 변경 사항을 모를 수 있음
- 자원 사용: AI 모델 실행에 CPU·RAM·GPU 필요
- 보안 위험: 로그에 포함된 비밀번호·토큰 등의 유출 가능성

AI가 제시한 장애 원인은 반드시 실제 서버 상태로 검증해야 한다.

### 7. Marble AIOps 적용

최종적으로 구축할 시스템의 흐름:

1. Marble 서버에서 장애 발생
2. Zabbix가 장애 감지
3. Python이 서버 상태와 로그 수집
4. Ollama + Qwen이 장애 원인 가설과 대응 방법 생성
5. Python이 안전한 복구 조건 확인
6. 허용된 단순 장애에 대해 자동 복구
7. 정상 여부 검증 및 Discord 알림

**중요:** AI가 생성한 명령어를 무조건 실행하는 것이 아니라, 미리 정의한 안전한 복구 정책에 따라 실행해야 한다.

### 8. 반드시 기억할 핵심 5가지

1. 생성형 AI는 새로운 텍스트·코드·이미지 등을 생성한다.
2. LLM은 문맥을 참고하여 다음 토큰을 예측하는 방식으로 답변을 생성한다.
3. Ollama는 AI 실행 프로그램이고 Qwen은 AI 모델이다.
4. AI는 환각이 발생할 수 있으므로 결과 검증이 필요하다.
5. Marble AIOps에서는 생성형 AI를 장애 분석에 활용하고, 실제 복구는 별도의 안전한 자동화 시스템이 수행한다.

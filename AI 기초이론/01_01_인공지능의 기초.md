## 1. AI(인공지능)란?

### 1.1 AI의 정의

AI는 **Artificial Intelligence(인공지능)**의 약자이다.

사람의 지능이 필요한 작업을 컴퓨터가 수행하도록 만드는 기술을 의미한다.

예를 들어 사람은 다음과 같은 작업을 할 수 있다.

- 사진을 보고 고양이와 강아지를 구별한다.
- 문장을 읽고 질문에 답변한다.
- 여러 정보를 비교해 문제의 원인을 추론한다.
- 과거 경험을 바탕으로 미래 상황을 예측한다.

AI는 이러한 작업을 컴퓨터가 수행하도록 만든다.

단, AI가 사람과 동일한 방식으로 생각하거나 의식을 가진다는 의미는 아니다.

### 1.2 AI의 활용 사례

| 분야 | 활용 사례 |
|---|---|
| 이미지 인식 | 사진 속 사람이나 사물 구분 |
| 자연어 처리 | 질문에 답변하거나 문서 분석 |
| 음성 인식 | 사람의 말을 텍스트로 변환 |
| 데이터 분석 | 이상 패턴 발견 및 예측 |
| IT 인프라 운영 | 장애 로그 분석, 원인 추론, 대응 방법 추천 |

**핵심:** AI는 특정 프로그램 하나를 의미하는 것이 아니라 다양한 지능적 작업을 수행하는 기술 분야이다.

## 2. AI는 왜 등장했을까?

### 2.1 기존 프로그램의 동작 방식

기존 프로그램은 사람이 작성한 규칙에 따라 동작하는 경우가 많다.

예를 들어 Zabbix에서 다음과 같이 설정했다고 가정한다.

- CPU 사용률이 95% 이상이다.
- 이 상태가 5분 이상 유지된다.
- 조건을 만족하면 Discord에 경고를 전송한다.

이를 간단하게 표현하면 다음과 같다.

`IF CPU >= 95% AND 지속시간 >= 5분 THEN 경고 전송`

이처럼 사람이 미리 작성한 조건을 기준으로 동작하는 방식을 **규칙 기반(Rule-based) 자동화**라고 한다.

#### 규칙 기반 방식의 장점

- 동작 조건이 명확하다.
- 결과를 예측하기 쉽다.
- 테스트 및 검증이 비교적 쉽다.
- 정해진 작업을 안정적으로 반복할 수 있다.

### 2.2 규칙 기반 방식의 한계

규칙 기반 방식은 명확한 조건을 처리하는 데 효과적이다.

하지만 현실의 모든 상황을 미리 규칙으로 작성하기는 어렵다.

예를 들어 Marble 프로젝트의 WAS01에서 다음 문제가 동시에 발생했다고 가정한다.

1. CPU 사용률이 95%까지 증가한다.
2. HTTP 응답 시간이 8초로 증가한다.
3. Jenkins에서 새로운 버전을 배포한 지 3분이 지났다.

여기서 CPU 사용률이 높다는 사실만으로 장애 원인을 확정할 수 있을까?

그렇지 않다.

가능한 원인은 다음과 같다.

- 정상적인 사용자 요청이 갑자기 증가했을 수 있다.
- 신규 애플리케이션에 성능 문제가 있을 수 있다.
- 무한 반복문이나 비효율적인 코드가 실행 중일 수 있다.
- 다른 프로세스가 CPU를 과도하게 사용하고 있을 수 있다.

즉, CPU 사용률이 높다는 사실은 확인되었지만 **왜 높아졌는지**는 추가 분석이 필요하다.

### 2.3 AI를 활용하는 이유

AI는 여러 정보를 분석하여 관련된 패턴을 찾아내거나 원인 가설을 제시하는 데 활용할 수 있다.

예를 들어 다음 정보를 AI에 전달한다고 가정한다.

- Zabbix CPU 사용률
- HTTP 응답 시간
- 애플리케이션 오류 로그
- Jenkins 최근 배포 시각

AI는 다음과 같은 분석을 생성할 수 있다.

> 최근 애플리케이션 배포 이후 CPU 사용률과 응답 시간이 증가했습니다. 배포된 애플리케이션의 성능 문제일 가능성이 있으므로 배포 전후의 메트릭과 오류 로그를 비교해 보세요.

이처럼 AI는 단순한 임계치 감지를 넘어 여러 정보를 함께 분석하는 데 도움을 줄 수 있다.

단, AI가 제시한 원인이 반드시 정답인 것은 아니다.

**핵심:** AI는 규칙 기반 프로그램을 완전히 대체하기보다 규칙만으로 처리하기 어려운 작업을 보완하는 데 활용된다.

## 3. 기존 프로그램과 AI의 차이

| 구분 | 규칙 기반 프로그램 | 학습 기반 AI |
|---|---|---|
| 판단 기준 | 사람이 작성한 규칙 | 학습한 패턴과 입력 데이터 |
| 동작 | 조건에 따른 정해진 처리 | 예측·분류·분석·생성 |
| 새로운 상황 | 새로운 규칙이 필요할 수 있음 | 학습한 패턴을 새로운 입력에 적용 |
| 장점 | 명확한 조건과 예측 가능한 결과 | 복잡한 데이터 및 패턴 처리 |
| 단점 | 모든 상황을 규칙으로 정의하기 어려움 | 부정확한 결과가 나올 수 있음 |
| 인프라 예시 | CPU 95% 이상이면 경고 | 메트릭·로그·배포 이력 종합 분석 |

### 3.1 AI가 항상 더 좋은 것은 아니다

다음 작업에는 굳이 AI가 필요하지 않다.

- CPU 사용률이 95% 이상이면 경고
- 디스크 사용률이 90% 이상이면 알림
- 특정 서비스가 중단되면 상태 확인
- 정해진 시간에 백업 실행

이런 작업은 기존 자동화 방식이 더 단순하고 검증하기 쉽다.

반면 다음 작업에는 AI가 유용할 수 있다.

- 수많은 오류 로그를 분석하고 요약
- 여러 서버에서 발생한 장애의 연관성 분석
- 최근 배포와 장애 발생 시점의 관계 조사
- 가능한 장애 원인과 확인 방법 추천

따라서 IT 운영에서는 **규칙 기반 자동화와 AI를 함께 사용하는 것이 중요하다.**

## 4. AI는 어떤 원리로 동작할까?

AI에는 여러 종류와 구현 방식이 있다.

여기서는 데이터를 통해 학습하는 AI의 기본적인 동작 구조를 이해한다.

### 4.1 전체 흐름

① 학습 데이터 준비
↓
② 모델 학습(Training)
↓
③ 학습된 AI 모델 생성
↓
④ 새로운 데이터 입력
↓
⑤ 추론(Inference)
↓
⑥ 분석 또는 예측 결과 출력

### 4.2 학습(Training)

학습이란 AI 모델이 데이터를 처리하면서 패턴을 익히도록 내부 수치를 조정하는 과정이다.

예를 들어 다양한 이미지와 해당 이미지의 정답 정보를 활용해 학습한 모델은 새로운 이미지가 주어졌을 때 어떤 동물인지 분류할 수 있다.

학습 과정에는 일반적으로 많은 데이터와 컴퓨팅 자원이 필요할 수 있다.

### 4.3 추론(Inference)

추론은 **이미 학습된 모델에 새로운 입력을 전달하여 결과를 얻는 과정**이다.

예를 들어 다음과 같다.

- 입력: "MySQL Communications link failure 오류의 원인은?"
- 모델: 이미 학습된 언어 모델
- 출력: 가능한 원인 및 확인 방법

우리가 앞으로 사용할 Qwen은 이미 학습된 AI 모델이다.

따라서 직접 AI 모델을 처음부터 학습시키지 않아도 된다.

### 4.4 Training과 Inference의 차이

| 구분 | Training | Inference |
|---|---|---|
| 의미 | AI 모델을 학습시키는 과정 | 학습된 모델을 사용하는 과정 |
| 입력 | 학습 데이터 | 새로운 질문이나 데이터 |
| 목적 | 데이터의 패턴 학습 | 분석·예측·응답 생성 |
| Marble 적용 | 직접 수행할 계획 없음 | 장애 로그를 입력해 분석 |

**핵심:** 우리가 진행할 AIOps 프로젝트에서는 이미 학습된 모델을 가져와 추론 기능을 활용한다.

## 5. AI는 어떤 작업을 할 수 있을까?

### 5.1 분류(Classification)

입력 데이터를 정해진 범주로 구분한다.

예시:
- 정상 로그와 오류 로그 분류
- 스팸 메일과 정상 메일 구분

### 5.2 예측(Prediction)

과거 데이터의 패턴을 활용해 미래의 값이나 상태를 예측한다.

예시:
- 서버 자원 사용량 증가 추세 예측
- 트래픽 수요 예측

### 5.3 이상 탐지(Anomaly Detection)

일반적인 패턴과 다른 데이터를 발견한다.

예시:
- 평소보다 갑자기 증가한 응답 시간 감지
- 비정상적인 네트워크 트래픽 패턴 감지

### 5.4 생성(Generation)

새로운 텍스트, 이미지, 코드 등을 생성한다.

예시:
- 장애 분석 보고서 작성
- Linux 명령어 설명
- Python 자동화 코드 작성

### 5.5 원인 분석 지원

여러 정보를 바탕으로 가능한 원인과 추가 확인 방법을 제시한다.

예시:
- WAS 장애 로그와 DB 연결 실패 정보 분석
- 최근 Jenkins 배포와 오류 증가의 연관성 분석

다만 이러한 결과는 실제 시스템 상태를 확인하여 검증해야 한다.

## 6. AI의 한계와 주의사항

### 6.1 AI는 항상 정확하지 않다

AI는 잘못된 답변을 생성할 수 있다.

특히 실제로 확인되지 않은 내용을 사실처럼 설명할 수 있는데, 이를 **환각(Hallucination)**이라고 한다.

### 6.2 실제 장애 사례

Marble WAS에서 다음 오류가 발생했다고 가정한다.

`Communications link failure`

AI는 다음과 같이 분석할 수 있다.

> MySQL 서비스가 중단되었을 가능성이 있습니다.

하지만 실제 원인은 다음 중 하나일 수 있다.

- MySQL 서비스 중단
- Security Group에서 3306 포트 차단
- MySQL bind-address 설정 문제
- DB 서버 네트워크 장애
- 연결 설정 오류

따라서 AI의 답변만으로 원인을 확정하면 안 된다.

### 6.3 AI 결과를 검증하는 방법

AI가 MySQL 중단 가능성을 제시했다면 다음 작업을 수행한다.

1. MySQL 서비스 상태 확인
2. DB 서버의 3306 포트 확인
3. WAS와 DB 사이의 네트워크 연결 확인
4. Security Group 및 DB 설정 확인
5. 수집된 결과로 실제 원인 판단

**핵심:** AI는 장애 원인 분석을 지원하지만, 실제 장애 여부와 복구 성공 여부는 시스템 검증을 통해 확인해야 한다.

## 7. Marble 프로젝트에 AI를 도입하는 이유

### 7.1 기존 Marble 운영 방식

현재 Marble 프로젝트에서는 다음 기술을 사용한다.

- AWS: WEB/WAS/DB 인프라 운영
- Zabbix: 서버 상태 및 장애 감지
- Discord: 장애 알림
- Jenkins: CI/CD 자동 배포

기존 장애 대응 과정은 다음과 같다.

① Marble 서버 장애 발생
↓
② Zabbix 장애 감지
↓
③ Discord 알림
↓
④ 운영자가 서버 상태와 로그 확인
↓
⑤ 운영자가 장애 원인 분석
↓
⑥ 운영자가 복구 작업 수행

즉, 장애 감지와 알림은 자동화되어 있지만 상세 원인 분석 및 복구는 주로 운영자가 수행하는 구조이다.

### 7.2 앞으로 구축할 Marble AIOps

최종 목표는 다음과 같다.

① Marble WEB/WAS/DB 장애 발생
↓
② Zabbix 장애 감지
↓
③ Python 프로그램으로 장애 정보 수집
↓
④ ELK에서 관련 로그 조회
↓
⑤ AI 모델(Qwen)이 장애 원인 가설 및 대응 방법 생성
↓
⑥ Python 복구 정책 엔진이 실제 상태 및 안전 조건 확인
↓
⑦ 허용된 단순 장애에 대해 복구 스크립트 실행
↓
⑧ 정상 복구 여부 확인
↓
⑨ Discord 알림 및 장애 이력 저장

여기서 중요한 것은 각 기술의 역할이다.

| 기술 | 역할 |
|---|---|
| AWS | Marble 서비스 인프라 운영 |
| Zabbix | 장애 감지 |
| ELK | 로그 수집·저장·검색 |
| Python | 장애 정보 수집 및 자동화 프로그램 |
| Ollama | AI 모델 실행 환경 |
| Qwen | 장애 정보 분석 및 원인 가설 생성 |
| 복구 정책·스크립트 | 허용된 복구 작업 실행 |
| Discord | 분석·복구 결과 알림 |

위 구조는 앞으로 구현할 목표이며, 현재 모든 기능이 완성된 것은 아니다.

### 7.3 AI가 직접 복구하는 것인가?

반드시 그렇지는 않다.

AI는 분석 결과를 제공하고, 복구 실행 여부는 사전에 정의된 정책과 실제 시스템의 검증 결과로 판단하도록 설계한다.

예를 들어 WAS01의 Spring Boot 서비스가 중단되었을 때:

1. WAS01 서비스 중단 여부 확인
2. WAS02 정상 여부 확인
3. DB 등 공통 장애 여부 확인
4. 기존 systemd 자동 재시작과 중복되지 않는지 확인
5. 사전에 허용한 조건을 만족하면 복구 스크립트 실행
6. `/health`와 서비스 상태로 복구 성공 여부 확인

조건을 충족하지 못하거나 복구에 실패하면 자동 실행을 중단하고 운영자에게 알리도록 한다.

**자동 복구의 핵심은 AI가 임의로 명령을 실행하는 것이 아니라, 미리 검증한 안전한 복구 절차를 수행하는 것이다.**

## 8. 자주 헷갈리는 개념

### Q1. AI와 ChatGPT는 같은 것인가?

아니다.

AI는 넓은 기술 분야이며, ChatGPT는 AI 기술을 활용한 서비스이다.

### Q2. AI와 자동화는 같은 것인가?

아니다.

자동화는 사람이 반복적으로 수행하는 작업을 프로그램이 대신하도록 만드는 것이다.

AI 없이도 자동화할 수 있다.

예를 들어 Jenkins 자동 배포나 Zabbix 임계치 알림은 AI 모델 없이 구현할 수 있다.

### Q3. AI를 사용하려면 반드시 직접 개발해야 하는가?

아니다.

이미 만들어진 AI 모델을 다운로드하거나 외부 API를 이용할 수 있다.

우리는 기존 모델을 활용하고, Python으로 Marble 인프라와 연결하는 프로그램을 개발할 예정이다.

### Q4. Ollama와 Qwen은 무엇인가?

- Ollama: AI 모델을 로컬 서버에서 실행하는 프로그램
- Qwen: 이미 학습된 AI 모델

Ollama가 Qwen 모델을 실행하고, Python이 Ollama API로 질문을 전달하는 방식으로 사용할 수 있다.

자세한 원리는 2장에서 학습한다.

### Q5. AI를 도입하면 모든 장애가 자동 복구되는가?

아니다.

단순하고 안전 조건이 명확한 일부 장애는 자동 복구하도록 구현할 수 있다.

하지만 DB 데이터 손실 가능성이 있거나 복잡한 네트워크 장애는 운영자의 확인과 승인이 필요할 수 있다.

## 9. 핵심 개념 최종 정리

| 개념 | 설명 |
|---|---|
| AI | 사람의 지능이 필요한 작업을 컴퓨터가 수행하도록 만드는 기술 |
| Rule-based | 사람이 작성한 규칙으로 동작하는 방식 |
| Training | 데이터를 사용하여 AI 모델을 학습시키는 과정 |
| Inference | 학습된 AI 모델에 새 입력을 전달해 결과를 얻는 과정 |
| Classification | 데이터를 종류별로 구분 |
| Prediction | 데이터 패턴을 활용해 값이나 상태 예측 |
| Anomaly Detection | 평소와 다른 이상 패턴 탐지 |
| Generation | 텍스트·이미지·코드 등 생성 |
| Hallucination | AI가 사실과 다르거나 근거 없는 내용을 생성하는 현상 |
| AIOps | AI 기술을 IT 운영의 감지·분석·대응 등에 활용하는 분야 |

## 10. 복습 확인문제 및 정답

### 문제 1
AI(인공지능)에 대한 설명으로 가장 적절한 것은?

1. 반드시 사람처럼 의식을 가지는 프로그램
2. 사람의 지능이 필요한 작업을 컴퓨터가 수행하도록 만드는 기술
3. 서버를 자동으로 재시작하는 Linux 명령어
4. 데이터를 저장하는 데이터베이스

**정답: 2번**

해설: AI는 인식, 예측, 언어 처리 등 다양한 지능적인 작업을 수행하도록 하는 기술이다.

### 문제 2
Zabbix에서 CPU 사용률이 95% 이상이면 경고를 보내도록 설정했다. 이는 무엇인가?

1. 딥러닝 모델 학습
2. AI 모델 재학습
3. 규칙 기반 자동화
4. 자연어 생성

**정답: 3번**

해설: 사람이 사전에 작성한 조건을 기반으로 동작하기 때문에 규칙 기반 자동화이다.

### 문제 3
이미 학습된 Qwen 모델에 장애 로그를 입력하여 분석 결과를 받는 과정은?

1. Training
2. Inference
3. Backup
4. Replication

**정답: 2번**

해설: 이미 학습된 모델을 이용하여 새로운 입력에 대한 결과를 생성하는 과정은 추론(Inference)이다.

### 문제 4
AI가 MySQL 장애 원인을 '서비스 중단'이라고 답변했을 때 올바른 대응은?

1. AI 답변을 확정된 원인으로 간주한다.
2. 즉시 MySQL 데이터를 삭제한다.
3. 무조건 서버를 재부팅한다.
4. 실제 서비스와 연결 상태를 확인하여 검증한다.

**정답: 4번**

해설: AI의 분석 결과가 틀릴 수도 있으므로 실제 서비스 상태와 로그 등을 확인해야 한다.

### 문제 5
Marble AIOps에서 AI가 담당하기에 가장 적절한 역할은?

1. 모든 서버를 무조건 자동 재시작한다.
2. 운영자 승인 없이 모든 DB를 삭제한다.
3. 장애 증거를 분석하고 원인 가설과 대응 방법을 제시한다.
4. AWS 이용 요금 없이 모든 서버를 운영한다.

**정답: 3번**

해설: AI는 장애 분석을 지원하며 실제 복구는 사전에 정의된 안전한 운영 정책을 통해 수행한다.

## 11. 이번 교시에서 반드시 기억할 5가지

1. **AI는 사람의 지능이 필요한 작업을 컴퓨터가 수행하도록 만드는 기술이다.**

2. **기존 규칙 기반 자동화는 명확한 조건을 처리하는 데 강하고, AI는 복잡한 패턴과 정보를 분석하는 데 활용할 수 있다.**

3. **Training은 모델을 학습시키는 과정이고, Inference는 학습된 모델을 사용하는 과정이다.**

4. **AI가 제시한 장애 원인은 가설일 수 있으므로 실제 서버 상태를 확인하여 검증해야 한다.**

5. **Marble AIOps의 목표는 장애 감지 → AI 분석 → 안전 조건 확인 → 허용된 복구 → 결과 검증을 자동화하는 것이다.**

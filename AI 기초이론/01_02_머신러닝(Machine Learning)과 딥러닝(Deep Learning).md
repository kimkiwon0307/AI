# 1. 지난 교시 복습 — AI란 무엇인가?

AI(Artificial Intelligence)는 **사람의 지능이 필요한 작업을 컴퓨터가 수행하도록 만드는 기술**이다.

AI를 활용하면 이미지 인식, 질문 답변, 예측, 이상 탐지, 문제 원인 분석 등의 작업을 수행할 수 있다.

기존 규칙 기반 프로그램과 AI의 차이를 먼저 살펴보자.

### 규칙 기반 자동화

예를 들어 Zabbix에서 다음 규칙을 설정했다고 가정한다.

- CPU 사용률이 95% 이상이다.
- 해당 상태가 5분 이상 유지된다.
- 조건을 만족하면 Discord로 경고를 전송한다.

이것은 사람이 정한 조건에 따라 동작하는 **규칙 기반(Rule-based) 자동화**이다.

### AI를 활용한 방식

CPU 사용률이 95%에 도달하지 않았더라도 평소 사용량과 비교해 비정상적으로 증가했다면 이상 징후로 판단할 수 있다.

예를 들어 평소 CPU 사용률이 10~20%인 서버에서 갑자기 80%까지 증가했다면 과거 데이터와 비교하여 이상 패턴을 탐지하도록 만들 수 있다.

이처럼 데이터의 패턴을 학습하여 새로운 상황에 활용하는 대표적인 기술이 **머신러닝**이다.

# 2. 머신러닝(Machine Learning)이란?

## 2.1 머신러닝의 정의

머신러닝은 한국어로 **기계학습**이라고 한다.

컴퓨터가 데이터에서 패턴을 학습하고, 학습한 패턴을 새로운 데이터의 예측이나 판단에 활용하는 기술이다.

예를 들어 다음과 같은 작업을 수행할 수 있다.

- 과거 데이터를 이용한 CPU 사용률 예측
- 정상 로그와 장애 로그 분류
- 비정상적인 네트워크 트래픽 탐지
- 서버의 자원 사용량 패턴 분석

머신러닝은 AI의 하위 분야에 해당한다.

## 2.2 머신러닝은 왜 등장했을까?

기존 프로그램에서는 사람이 직접 판단 규칙을 작성해야 하는 경우가 많다.

예를 들어 다음과 같이 설정할 수 있다.

```text
CPU >= 95% → 장애 경고
MEMORY >= 95% → 장애 경고
DISK >= 90% → 장애 경고
```

하지만 실제 운영 환경에서는 단순한 임계치만으로 모든 상황을 구분하기 어렵다.

예를 들어 CPU 사용률이 80%라고 가정하자.

- 평소 CPU가 10%인 서버라면 비정상적인 증가일 수 있다.
- 평소 CPU가 75%인 서버라면 일반적인 상황일 수 있다.
- 정기 백업 작업 중이라면 정상적인 부하일 수 있다.
- 애플리케이션 오류 때문에 CPU가 증가했을 수도 있다.

즉, **동일한 CPU 사용률이라도 서버의 평소 패턴과 상황에 따라 의미가 달라진다.**

머신러닝은 이런 복잡한 패턴을 데이터에서 학습하는 데 활용할 수 있다.

## 2.3 기존 프로그램과 머신러닝의 차이

| 구분 | 규칙 기반 프로그램 | 머신러닝 |
|---|---|---|
| 판단 기준 | 사람이 작성한 조건 | 데이터에서 학습한 패턴 |
| 새로운 상황 | 규칙 추가가 필요할 수 있음 | 학습된 패턴을 활용 |
| 장점 | 동작이 명확하고 검증이 쉬움 | 복잡한 데이터 패턴 분석 가능 |
| 단점 | 모든 상황을 규칙화하기 어려움 | 학습 데이터와 모델 품질에 영향받음 |
| 활용 예시 | CPU 95% 이상 경고 | 평소와 다른 CPU 패턴 탐지 |

**핵심:** 머신러닝은 사람이 모든 판단 조건을 일일이 작성하는 대신, 데이터의 패턴을 학습하여 결과를 도출하는 기술이다.

# 3. 머신러닝의 동작 원리

머신러닝의 기본적인 흐름은 다음과 같다.

```text
① 데이터 수집
       ↓
② 데이터 준비 및 전처리
       ↓
③ 머신러닝 알고리즘 선택
       ↓
④ 모델 학습(Training)
       ↓
⑤ 모델 평가
       ↓
⑥ 새로운 데이터 입력
       ↓
⑦ 추론(Inference)
       ↓
⑧ 예측·분류·이상 탐지 결과
```

## 3.1 데이터 수집

머신러닝은 학습할 데이터가 필요하다.

예를 들어 Marble WAS01에서 Zabbix로 수집한 CPU 사용량을 생각해 보자.

| 시간 | CPU 사용률 |
|---|---:|
| 09:00 | 12% |
| 10:00 | 15% |
| 11:00 | 18% |
| 12:00 | 20% |
| 13:00 | 14% |
| 14:00 | 16% |
| 15:00 | 82% |

이 예시에서는 15시에 CPU 사용률이 크게 증가했다.

하지만 이것만으로 장애가 확정되는 것은 아니다.

이 데이터가 실제로 비정상인지 판단하려면 더 오랜 기간의 데이터나 서버 상태 정보가 필요할 수 있다.

## 3.2 데이터 전처리(Preprocessing)

데이터를 수집했다고 바로 학습에 사용할 수 있는 것은 아니다.

예를 들어 다음과 같은 문제가 있을 수 있다.

- 일부 시간대의 데이터가 누락됨
- CPU 사용률이 비정상적인 형식으로 저장됨
- 서로 다른 서버의 데이터가 섞여 있음
- 수집 시간이 일치하지 않음

이러한 데이터를 정리하고 모델에 맞는 형태로 변환하는 작업을 **데이터 전처리**라고 한다.

## 3.3 모델 학습(Training)

준비된 데이터를 머신러닝 알고리즘에 제공한다.

알고리즘은 학습 목표에 따라 데이터에 포함된 패턴을 학습한다.

예를 들어 정상적인 CPU 사용량 패턴을 학습하도록 모델을 구성할 수 있다.

이때 학습한 패턴을 바탕으로 새로운 데이터에 결과를 출력하는 핵심 구조를 **모델(Model)**이라고 한다.

### 모델이란?

모델은 학습을 통해 얻은 내부 수치나 구조를 이용해 새로운 입력에 대한 결과를 만드는 계산 시스템이다.

단순히 말하면 다음과 같다.

- 학습 전: 데이터의 패턴을 충분히 반영하지 못한 상태
- 학습 중: 데이터를 처리하며 모델 내부 수치를 조정
- 학습 후: 새로운 데이터에 대해 결과를 출력할 수 있는 상태

## 3.4 모델 평가(Evaluation)

학습한 모델이 제대로 작동하는지 확인해야 한다.

예를 들어 학습에 사용하지 않은 데이터로 평가할 수 있다.

여기서 중요한 점은 **학습 데이터에서 잘 작동한다고 새로운 데이터에서도 정확하다는 보장은 없다는 것**이다.

따라서 모델은 반드시 별도의 데이터를 이용해 성능을 평가해야 한다.

## 3.5 추론(Inference)

추론은 이미 학습된 모델에 새로운 데이터를 전달해 결과를 얻는 과정이다.

예를 들어 현재 CPU 사용률이 82%일 때 모델이 과거 패턴과 비교하여 이상 징후를 출력할 수 있다.

```text
현재 CPU 사용률: 82%
        ↓
학습된 머신러닝 모델
        ↓
평소 사용량 패턴과 비교
        ↓
이상 징후 가능성 출력
```

실제 모델이 이 값을 이상으로 판단할지는 학습 데이터와 알고리즘에 따라 달라진다.

### Training과 Inference 비교

| 구분 | Training(학습) | Inference(추론) |
|---|---|---|
| 의미 | 모델이 패턴을 학습 | 학습된 모델을 사용 |
| 입력 | 학습 데이터 | 새로운 데이터 |
| 목적 | 모델 내부 수치 조정 | 예측·분류·결과 생성 |
| Marble 활용 | 선택적인 ML 모델 학습 | Qwen 등의 AI 모델 활용 |

**중요:** 우리가 Marble AIOps에서 사용할 Qwen은 이미 학습된 모델이다.

따라서 처음부터 직접 모델을 학습시키지 않아도 추론 기능을 이용할 수 있다.

# 4. 머신러닝의 대표적인 학습 방식

머신러닝에는 여러 학습 방식이 존재한다.

대표적으로 다음 세 가지가 있다.

1. 지도학습(Supervised Learning)
2. 비지도학습(Unsupervised Learning)
3. 강화학습(Reinforcement Learning)

## 4.1 지도학습(Supervised Learning)

### 개념

**정답(Label)이 포함된 데이터를 이용해 학습하는 방법**이다.

예를 들어 다음과 같은 장애 로그가 있다고 가정한다.

| 로그 | 정답(Label) |
|---|---|
| Connection refused | 연결 장애 |
| OutOfMemoryError | 메모리 오류 |
| Disk space exhausted | 디스크 부족 |
| HTTP 200 OK | 정상 |

여기서는 각 로그에 정답이 표시되어 있다.

모델은 로그와 정답 사이의 관계를 학습하고, 새로운 로그에 대해 장애 유형을 예측할 수 있다.

### 동작 원리

```text
장애 로그 + 정답(Label)
          ↓
      지도학습
          ↓
     학습된 모델
          ↓
    새로운 장애 로그
          ↓
    장애 유형 예측
```

### 대표적인 작업

**분류(Classification)**

데이터가 어떤 종류에 속하는지 판단한다.

예시:
- 정상 / 장애 구분
- DB 장애 / 네트워크 장애 / 메모리 장애 분류

**회귀(Regression)**

연속적인 숫자 값을 예측한다.

예시:
- 다음 시간대 CPU 사용률 예측
- 예상 네트워크 트래픽 예측

### 장점과 한계

장점:
- 정답이 있는 데이터를 이용해 목표를 명확하게 학습할 수 있다.
- 예측 결과를 실제 정답과 비교하여 평가할 수 있다.

한계:
- 정답 데이터를 확보해야 한다.
- 정답 표시가 잘못되면 학습 품질이 떨어질 수 있다.
- 학습하지 않은 유형의 장애를 정확하게 구분하지 못할 수 있다.

---

## 4.2 비지도학습(Unsupervised Learning)

### 개념

**정답이 표시되지 않은 데이터에서 구조나 패턴을 발견하는 학습 방법**이다.

예를 들어 Zabbix에서 다음 데이터를 수집했다고 가정한다.

- CPU 사용률
- 메모리 사용률
- 네트워크 사용량
- 디스크 I/O

각 데이터에는 정상인지 장애인지 정답이 표시되어 있지 않다.

비지도학습은 이러한 데이터가 어떤 형태로 모이는지, 서로 얼마나 비슷한지 등을 분석할 수 있다.

### 동작 원리

```text
정답이 없는 서버 메트릭
          ↓
       비지도학습
          ↓
    데이터 패턴 발견
          ↓
  일반적인 패턴과 다른 데이터 확인
```

### 대표적인 작업

**군집화(Clustering)**

비슷한 특징을 가진 데이터끼리 묶는 작업이다.

예시:
- CPU와 메모리 사용 패턴이 비슷한 서버 그룹 구분
- 사용량 패턴에 따른 서버 분류

**이상 탐지(Anomaly Detection)**

일반적인 패턴과 다른 데이터를 발견하는 작업이다.

예시:
- 평소와 다른 CPU 사용량 변화
- 비정상적인 네트워크 트래픽 패턴

단, 이상 탐지는 반드시 비지도학습으로만 구현하는 것은 아니다. 지도학습이나 통계적 방법도 사용할 수 있다.

### 주의사항

모델이 이상한 패턴을 발견했다고 해서 반드시 장애를 의미하는 것은 아니다.

예를 들어 정기적인 백업 작업도 평소와 다른 자원 사용 패턴을 만들 수 있다.

따라서 실제 장애인지 추가 검증해야 한다.

## 4.3 강화학습(Reinforcement Learning)

### 개념

**행동을 수행하고 그 결과로 얻은 보상(Reward)을 활용해 더 좋은 행동을 학습하는 방법**이다.

쉽게 이해하기 위해 게임 AI를 생각해 보자.

- 좋은 선택 → 높은 보상
- 나쁜 선택 → 낮은 보상
- 반복적으로 선택하면서 더 좋은 행동을 학습

### 동작 원리

```text
현재 상태 확인
       ↓
    행동 선택
       ↓
    행동 실행
       ↓
    결과 확인
       ↓
    보상 획득
       ↓
  더 좋은 행동 학습
```

### 인프라 분야 활용 예시

가상의 서버 운영 시뮬레이션 환경에서 리소스 배분 정책을 학습시키는 경우를 생각할 수 있다.

- 서버 자원을 효율적으로 배분
- 응답 시간을 줄이는 방향으로 정책 학습
- 비용과 성능을 함께 고려한 정책 실험

### 주의사항

실제 운영 서버에서 무작위로 서비스를 중단하거나 DB를 재시작하면서 강화학습을 시키는 것은 위험하다.

따라서 이러한 실험은 안전한 시뮬레이션 환경에서 진행해야 한다.

또한 우리가 만들 Marble AIOps의 1차 구현에는 강화학습이 필수는 아니다.

## 4.4 세 가지 학습 방식 비교

| 구분 | 지도학습 | 비지도학습 | 강화학습 |
|---|---|---|---|
| 학습 기준 | 정답 데이터 | 데이터의 구조·패턴 | 행동 결과의 보상 |
| 정답(Label) | 사용 | 일반적으로 사용하지 않음 | 정답 대신 보상 활용 |
| 대표 작업 | 분류·회귀 | 군집화·이상 탐지 | 행동 정책 학습 |
| 예시 | 장애 유형 분류 | 서버 사용량 패턴 분석 | 리소스 배분 정책 학습 |

### 암기 방법

- 지도학습: **정답을 알려주고 학습**
- 비지도학습: **정답 없이 패턴을 발견**
- 강화학습: **행동과 보상을 통해 학습**

---

# 5. 딥러닝(Deep Learning)이란?

## 5.1 딥러닝의 정의

딥러닝은 **여러 층으로 구성된 인공신경망(Artificial Neural Network)을 활용하여 데이터의 복잡한 패턴을 학습하는 머신러닝 기술**이다.

즉, 딥러닝은 머신러닝과 완전히 별개의 기술이 아니다.

딥러닝은 머신러닝의 하위 분야이다.

## 5.2 AI, 머신러닝, 딥러닝의 관계

```text
AI (Artificial Intelligence)
│
└── ML (Machine Learning)
    │
    └── DL (Deep Learning)
        │
        └── 현대적인 LLM
            ├── GPT
            ├── Qwen
            └── Llama
```

위 구조는 주요 기술들의 관계를 단순화한 것이다.

- AI: 인공지능 전체 분야
- 머신러닝: 데이터에서 패턴을 학습하는 AI 기술
- 딥러닝: 인공신경망을 활용하는 머신러닝 기술
- 현대적인 LLM: 대부분 딥러닝 기반의 언어 모델

**핵심: 딥러닝 ⊂ 머신러닝 ⊂ AI**

## 5.3 딥러닝은 왜 등장하고 발전했을까?

전통적인 머신러닝에서는 사람이 데이터의 중요한 특징을 직접 선택하거나 가공해야 하는 경우가 많았다.

예를 들어 서버 장애 예측 모델을 만든다면 다음 특징을 선택할 수 있다.

- CPU 사용률
- 메모리 사용률
- 응답 시간
- 디스크 I/O

이를 특징(Feature)이라고 한다.

딥러닝은 여러 층의 신경망을 이용해 입력 데이터에서 복잡한 특징과 패턴을 단계적으로 학습할 수 있다.

이러한 특성으로 이미지 인식, 음성 인식, 자연어 처리 등의 분야에서 널리 사용되고 있다.

다만 딥러닝이 모든 상황에서 기존 머신러닝보다 좋은 것은 아니다.

# 6. 인공신경망(Artificial Neural Network)이란?

인공신경망은 여러 계산 단위(인공 뉴런)를 연결하여 데이터를 처리하는 모델이다.

각 연결에는 학습 과정에서 조정되는 가중치(Weight)가 존재한다.

## 6.1 기본 구조

```text
입력 데이터
    ↓
입력층(Input Layer)
    ↓
은닉층(Hidden Layer)
    ↓
은닉층(Hidden Layer)
    ↓
출력층(Output Layer)
    ↓
예측 또는 분류 결과
```

### 입력층(Input Layer)

외부에서 받은 데이터를 신경망에 전달한다.

예를 들어 서버 모니터링 모델이라면 CPU, 메모리, 응답 시간 등의 수치가 입력될 수 있다.

### 은닉층(Hidden Layer)

입력 데이터를 여러 계산 단계를 거쳐 처리한다.

데이터의 복잡한 관계와 패턴을 학습하는 데 중요한 역할을 한다.

### 출력층(Output Layer)

최종 결과를 출력한다.

예시:
- 정상일 가능성
- 장애일 가능성
- 예상 CPU 사용률

실제 출력 방식은 모델의 목적에 따라 달라진다.

## 6.2 가중치(Weight)란?

가중치는 신경망에서 입력 정보가 계산 결과에 어떤 영향을 주는지를 결정하는 학습 가능한 수치이다.

모델은 학습 과정에서 이러한 가중치를 조정한다.

예를 들어 메모리 사용률과 장애 발생 사이에 관계가 있다면, 신경망은 데이터를 학습하면서 그 관계를 반영하는 계산 구조를 형성할 수 있다.

가중치는 사람이 모든 값을 일일이 설정하는 것이 아니라 학습 알고리즘에 의해 조정된다.

---

# 7. 딥러닝은 어떻게 학습할까?

지도학습 기반 신경망을 예로 들어보자.

## 7.1 데이터 입력

CPU, 메모리, 응답 시간 등의 데이터를 모델에 입력한다.

## 7.2 순전파(Forward Propagation)

입력 데이터가 신경망의 여러 층을 지나면서 계산된다.

최종적으로 예측 결과가 출력된다.

예를 들어 모델이 장애 가능성을 예측할 수 있다.

## 7.3 손실(Loss) 계산

모델의 예측 결과와 실제 정답의 차이를 계산한다.

이 차이를 나타내는 수치를 **손실(Loss)**이라고 한다.

예를 들어 실제 정답은 장애인데 모델이 정상으로 예측했다면, 학습 목표에 맞는 손실 함수가 그 차이를 반영한다.

## 7.4 역전파(Backpropagation)

역전파는 손실이 모델의 각 가중치에 어떻게 영향을 받는지 계산하는 방법이다.

이 정보를 이용해 최적화 알고리즘이 가중치를 조정한다.

## 7.5 반복 학습

모델은 이러한 과정을 반복하며 손실을 줄이는 방향으로 학습한다.

```text
학습 데이터 입력
       ↓
순전파(예측값 계산)
       ↓
손실(Loss) 계산
       ↓
역전파(기울기 계산)
       ↓
가중치 조정
       ↓
반복 학습
```

학습이 완료되면 새로운 데이터로 모델 성능을 평가한다.

**중요:** 손실이 감소했다고 해서 실제 운영 환경에서 반드시 정확하게 동작하는 것은 아니다.

# 8. 과적합(Overfitting)이란?

과적합은 머신러닝과 딥러닝에서 중요한 개념이다.

## 8.1 과적합의 정의

**모델이 학습 데이터에는 지나치게 잘 맞지만, 새로운 데이터에서는 성능이 떨어지는 현상**이다.

예를 들어 모델이 특정 시간대와 특정 서버에서 발생한 장애 데이터만 지나치게 학습했다고 가정하자.

학습 당시에는 높은 정확도를 보일 수 있다.

하지만 다른 서버나 새로운 장애 상황에서는 부정확한 결과를 낼 수 있다.

## 8.2 과적합이 발생하는 이유

대표적인 원인은 다음과 같다.

- 학습 데이터가 충분히 다양하지 않음
- 모델이 데이터에 비해 지나치게 복잡함
- 학습 데이터의 특수한 패턴까지 외워버림
- 학습 데이터에 과도하게 맞추어 학습함

## 8.3 과적합을 방지하려면?

대표적인 방법은 다음과 같다.

- 다양한 학습 데이터 확보
- 학습 데이터와 평가 데이터 분리
- 모델 복잡도 조절
- 적절한 학습 중단과 규제 기법 사용
- 새로운 데이터로 성능 검증

### 인프라 운영과 연결

Marble의 특정 WAS에서 수집한 데이터만으로 학습한 모델이 모든 서버에서 정확하게 동작한다고 보장할 수 없다.

따라서 실제 운영 환경에 적용할 때는 다양한 장애 상황과 정상 상황을 구분하여 검증해야 한다.

# 9. 머신러닝과 딥러닝의 차이

| 구분 | 머신러닝(ML) | 딥러닝(DL) |
|---|---|---|
| 관계 | AI의 하위 분야 | 머신러닝의 하위 분야 |
| 핵심 기술 | 다양한 학습 알고리즘 | 다층 인공신경망 |
| 특징 처리 | 사람이 특징을 설계하는 경우가 많음 | 여러 층에서 특징 학습 가능 |
| 데이터 요구량 | 알고리즘에 따라 다름 | 복잡한 모델은 많은 데이터가 유리 |
| 컴퓨팅 자원 | 적은 자원으로 가능한 방법도 많음 | 대규모 모델은 많은 자원 필요 |
| 대표 활용 | 분류·회귀·이상 탐지 | 이미지·음성·언어 처리 |
| 인프라 예시 | 서버 사용량 패턴 분석 | LLM 기반 장애 로그 분석 |

### 반드시 기억할 점

**딥러닝이 머신러닝보다 무조건 좋은 것은 아니다.**

예를 들어 서버 CPU, 메모리, 트래픽처럼 구조화된 수치 데이터를 분석할 때는 단순한 머신러닝 알고리즘이 더 효율적일 수 있다.

반면 방대한 텍스트 로그를 이해하고 장애 보고서를 생성하는 작업에는 LLM이 유용할 수 있다.

기술의 우수성을 이름으로 판단하기보다 문제에 적합한 방법을 선택해야 한다.

# 10. 머신러닝·딥러닝과 LLM의 관계

LLM은 Large Language Model의 약자로 **대규모 언어 모델**을 의미한다.

대표적인 모델 계열은 다음과 같다.

- GPT
- Qwen
- Llama

현대적인 LLM은 대부분 Transformer라는 신경망 구조에 기반한다.

Transformer의 자세한 동작 원리는 2장에서 학습할 예정이다.

현재는 다음 관계만 이해하면 충분하다.

```text
AI
 ↓
머신러닝
 ↓
딥러닝
 ↓
LLM
 ↓
Qwen
```

Qwen은 이미 학습된 LLM이다.

우리가 Ollama를 이용해 Qwen을 실행한다면 직접 딥러닝 모델을 처음부터 학습시키는 것이 아니다.

이미 학습된 모델에 질문을 입력하고 분석 결과를 받는 **추론(Inference)** 기능을 활용하는 것이다.

### Ollama와 Qwen의 차이

| 기술 | 역할 |
|---|---|
| Ollama | AI 모델 실행 및 API 제공 |
| Qwen | 언어 입력을 분석하고 결과를 생성하는 모델 |
| Python | AI 모델에 요청을 보내고 결과를 처리하는 프로그램 |

예를 들어 Python이 MySQL 장애 로그를 Ollama API에 전달하면, Ollama에서 실행 중인 Qwen이 원인 가설과 확인 방법을 생성할 수 있다.

# 11. Marble AIOps 프로젝트와 연결

이번 교시에서 배운 머신러닝과 딥러닝을 실제 Marble 프로젝트에 적용해 보자.

## 11.1 현재 Marble의 운영 방식

현재 프로젝트에는 다음 기술이 사용된다.

- AWS EC2: WEB/WAS/DB 서비스 운영
- Zabbix: CPU, 메모리, 디스크, 서비스 상태 모니터링
- Jenkins: CI/CD 배포
- Discord: 장애 알림

현재는 주로 정해진 임계치와 서비스 상태에 따라 장애를 감지한다.

이는 규칙 기반 모니터링 및 자동화 방식이다.

## 11.2 머신러닝 활용 — 이상 탐지

Zabbix에서 수집한 과거 CPU, 메모리, 네트워크 사용량을 머신러닝 모델에 학습시킬 수 있다.

이후 평소와 다른 사용량 패턴이 발생하면 이상 징후로 판단하도록 구성할 수 있다.

```text
Zabbix
   ↓
과거 서버 메트릭 수집
   ↓
머신러닝 모델 학습
   ↓
현재 메트릭 입력
   ↓
평소와 다른 패턴 탐지
```

다만 이 기능은 Marble AIOps의 선택적인 확장 기능이다.

처음부터 머신러닝 모델을 직접 개발할 필요는 없다.

## 11.3 딥러닝 활용 — LLM 장애 분석

우리가 우선 구현하려는 것은 이미 학습된 LLM을 이용한 장애 분석이다.

```text
Marble WAS01 장애 발생
          ↓
Zabbix 장애 감지
          ↓
Python 장애 정보 수집
          ↓
ELK 관련 로그 조회
          ↓
Ollama + Qwen
          ↓
장애 원인 가설 생성
          ↓
대응 방법 추천
```

예를 들어 WAS01에서 다음 오류가 발생했다고 가정한다.

`Communications link failure`

AI는 다음과 같은 원인 후보를 제시할 수 있다.

- MySQL 서비스 중단
- DB 서버 연결 실패
- Security Group 설정 문제
- 네트워크 경로 문제
- MySQL 리스닝 설정 문제

그러나 실제 원인은 추가적인 상태 점검으로 검증해야 한다.

## 11.4 안전한 자동 복구

AI 분석 이후 실제 복구는 별도의 정책에 따라 진행한다.

```text
장애 발생
   ↓
Zabbix 감지
   ↓
Python 정보 수집
   ↓
Qwen 원인 분석
   ↓
복구 정책 및 실제 상태 검증
   ↓
허용된 복구 작업 실행
   ↓
Health Check
   ↓
Discord 결과 보고
```

예를 들어 단순한 WAS 프로세스 중단이 확인되었다면, 운영 정책에 따라 서비스를 재시작할 수 있다.

```bash
sudo systemctl restart marble
```

단, 이 명령어를 AI가 출력했다고 바로 실행하는 것은 아니다.

- 실제 서비스 중단 여부 확인
- WAS02 정상 여부 확인
- DB 등 공통 장애 여부 확인
- 기존 systemd 자동 재시작과 중복 확인
- 재시도 횟수 제한
- 사전 승인된 작업인지 확인

위와 같은 안전 조건을 충족했을 때만 실행한다.

재시작 이후에는 `/health`와 필요한 서비스 상태를 확인하여 복구 성공 여부를 검증한다.

## 11.5 최종적으로 머신러닝 모델도 직접 개발해야 할까?

**반드시 그럴 필요는 없다.**

우리가 만들려는 Marble AIOps의 1차 목표는 다음과 같다.

1. Zabbix로 장애 감지
2. Python으로 장애 정보 수집
3. ELK로 관련 로그 조회
4. Qwen으로 장애 분석
5. 안전한 조건에서 복구 자동화
6. 복구 결과 검증

이 구조만으로도 AI를 활용한 장애 분석 및 운영 자동화 프로젝트를 구축할 수 있다.

향후 필요하다면 머신러닝 기반 이상 탐지를 추가해 시스템을 고도화할 수 있다.

# 12. 자주 헷갈리는 개념

### Q1. AI와 머신러닝은 같은가?

완전히 같지는 않다.

AI는 더 넓은 분야이고 머신러닝은 AI의 하위 분야이다.

AI에는 규칙 기반 시스템을 비롯해 다양한 접근 방식이 존재한다.

### Q2. 머신러닝과 딥러닝은 같은가?

딥러닝은 머신러닝의 한 종류이다.

딥러닝은 여러 층의 인공신경망을 활용한다는 특징이 있다.

### Q3. 머신러닝은 반드시 정답이 있는 데이터를 사용하나?

아니다.

지도학습은 정답을 사용하지만, 비지도학습은 정답 없이 데이터의 패턴이나 구조를 찾는다.

### Q4. 딥러닝을 배우려면 수학을 반드시 깊게 알아야 하나?

딥러닝 모델을 직접 설계·학습·연구하려면 수학적 이해가 중요하다.

하지만 이미 학습된 LLM을 활용하고 운영하는 초기 단계에서는 모델 사용법과 기본 원리부터 공부할 수 있다.

### Q5. Qwen을 사용하려면 직접 머신러닝을 학습시켜야 하나?

아니다.

Qwen은 이미 학습된 모델이다.

Ollama 등을 이용해 실행하고 추론 기능을 활용할 수 있다.

### Q6. AIOps와 머신러닝은 같은가?

아니다.

머신러닝은 데이터 학습 기술이고, AIOps는 AI 기술을 IT 운영에 적용하는 분야이다.

AIOps에는 머신러닝뿐 아니라 LLM, 규칙 기반 자동화, 모니터링, 운영 정책 등의 기술을 함께 활용할 수 있다.

### Q7. AI가 장애를 분석하면 자동 복구까지 알아서 하는가?

아니다.

장애 분석과 복구 실행은 서로 다른 작업이다.

AI가 원인 가설을 제시하고, 실제 복구는 사전에 정의한 안전한 정책과 자동화 절차에 따라 실행하도록 설계해야 한다.

# 16. 면접 대비 핵심 질문

### Q1. 머신러닝과 딥러닝의 차이는 무엇인가요?

머신러닝은 데이터를 통해 패턴을 학습하는 AI 기술이며, 딥러닝은 여러 층의 인공신경망을 활용하는 머신러닝의 한 종류입니다.

### Q2. 지도학습과 비지도학습의 차이는 무엇인가요?

지도학습은 정답이 포함된 데이터로 학습하고, 비지도학습은 정답 없이 데이터의 구조나 패턴을 찾는 방식입니다.

### Q3. AIOps를 구현하려면 머신러닝 모델을 직접 개발해야 하나요?

반드시 그렇지는 않습니다. 이미 학습된 LLM을 활용해 장애를 분석할 수 있으며, 모니터링과 자동화 기술을 결합하여 운영 시스템을 구현할 수 있습니다.

### Q4. AI의 분석 결과를 그대로 믿고 복구하면 안 되는 이유는 무엇인가요?

AI가 잘못된 원인이나 조치를 제시할 수 있기 때문입니다. 실제 서버 상태와 안전 조건을 검증한 후 사전에 허용된 복구 절차를 수행해야 합니다.
